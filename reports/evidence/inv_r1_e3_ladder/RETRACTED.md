# The embedded ladder in `e3-postfix-ladder.json` is a withdrawn result

`e3-postfix-ladder.json` is **not** retracted. It is the post-fix ladder and
its own numbers stand. One key inside it is not, and a reader cannot tell that
from the file.

`committed-ladder-status.json` is the machine-readable form of this notice.
Both are produced by `experiments/regen_v2/regen_e3_ladder_status.py`, which
re-measures the claim from the committed bytes on every run.

## B6 / N-80 — `$.committed_ladder` is the withdrawn ladder under a live-looking name

`$.committed_ladder` carries
`"policy_instance_scope": "shared-across-worlds"` and
`"path": "reports/evidence/inv_r1_e3_selection/e3-crossover.json"`. Its
per-budget `choices`, `held_out_reduction_mean`, `resources_used_total` and
`yield_totals` are **identical to `e3-crossover.json` at all six budgets**, and
this file's top-level `measure_digest` equals that file's.

It is a byte-level re-embedding of a result the sibling directory withdrew. A
reader who opens the post-fix artifact and reads `committed_ladder` sees the
pre-fix numbers under a key that names no withdrawal, and the JSON is what a
machine reads.

**Why it is annotated and not deleted.** It is the pre-fix/post-fix bridge.
The whole point of shipping both the pre-fix and post-fix ladders is that a
reader can compare them, and this key is where that comparison lives. Deleting
it would break the comparison permanently. The status marker is a sibling file
rather than an edit to the artifact, so the committed bytes survive as the
record of the defect.

To join it against the artifact:

```
jq --slurpfile m committed-ladder-status.json '$metadata' e3-postfix-ladder.json
```

## What the marker measured, not asserted

`committed-ladder-status.json` was generated by re-reading both committed files:

| | value |
|---|---|
| budgets compared | 6 |
| every budget agrees on every field | `true` |
| `measure_digest` equal across the two files | `true` |
| withdrawal words in the 165 KB artifact | `retract` 0, `withdrawn` 0, `invalid` 0, `superseded` 0 |

The last row is why the marker has to be a separate file. The artifact contains
no word that would warn a reader, and adding one would mean editing the bytes
this notice exists to preserve.

## What does not survive

`e3-crossover.json`'s own `agenda_ahead_on_held_out_at: [14, 60]` does not, and
neither does the control's `resources_used_total` read as an independent run
per budget. `crossover()` at `experiments/ad01/s09_e3_selection.py:133`
constructs each policy once with `policy = make_policy()` and only then enters
its world and budget loops, so both policies are stateful across all eighteen
cells and the control's totals are cumulative prefix sums of one traversal.
That is N-80, and it is `RETRACTED.md` cause 1 in the sibling directory.

## Method

Both runs' IDs were extracted the same way, from the runs' **own** per-shard
logs via `gh run view --job <id> --log`, never from a report. Each ID is a pytest
short-summary line matching `^(FAILED|ERROR)\s+(tests/\S+\.py::\S+)`, taken
after stripping Azure's `job\tSTEP\tTIMESTAMP\t` prefix. Logs are read with
Python `re`, per the standing warning that `grep -oE` returns zero from these
bytes.

The method is validated by the baseline reproducing: it yields **259 exactly**,
matching the committed `ci-baseline-37172638343.md`. A method that reproduces a
known number is trustworthy on the unknown one.

```
NEW   = current_ids - baseline_ids   =  13
FIXED = baseline_ids - current_ids   =  25
BOTH  = current_ids ∩ baseline_ids   = 234
                                       ---
                                       272 = 247 + 259 - 234
```

Shard membership did not drift: of the IDs failing in both runs, **zero** changed
shard. So FIXED is not an artifact of reshardization. Every FIXED test file still
exists at `91b36f8` (12, 25, 3, 27, 6 and 13 test defs respectively), and both
`py3.132` runs completed a full pass (1145 and 1123 passed), so none of them
aborted early.

**Cause 1. Stale test after the action-vocabulary gate widened (3).**

`dbe8471e` / `aefc7fa1` made `_validator_refuses` ask *every* action contract
rather than only `policy_step.validate_action`, because this host declares two
vocabularies. Two tests still assert the pre-widening world.

- `tests/test_c8_gate_review.py:333` `test_the_derivation_helpers_are_reachable_and_ask_the_validator`
- `tests/test_c9_override_order.py:331` `test_the_rule_still_asks_the_contract_rather_than_restating_it`

Both assert `not {"ACTION_REQUIRED", "ACTION_KINDS"} & names` over the bytecode
of `method_exec._validator_refuses`, intending to catch a restated list of inert
shapes. The gate now genuinely asks the contract, but it asks it through
`policy_step.ACTION_REQUIRED` as a real attribute load at `method_exec.py:1346`,
so the name appears in bytecode. Reproduced in the repo venv at `91b36f8`:

```
intersection: {'ACTION_REQUIRED'}
ALL str argvals: ['', 'ACTION_REQUIRED', 'ActionRefused', 'ValueError', 'any',
                  'dict', 'isinstance', 'literal', 'parse_action',
                  'policy_action', 'policy_step', 'validate_action']
```

The test is stale, not the gate. Its own docstring says the bytecode read exists
so a *docstring* cannot satisfy it. A body attribute load is a different thing
from a docstring, and the test cannot tell them apart. The docstring at
`method_exec.py:1312` names `ACTION_REQUIRED` too, so the check is now ambiguous
by construction.

- `tests/test_c8_gate_review.py:138` `test_a_newly_valid_literal_is_re_admitted_by_the_same_code`

expects the same `{"action": None}` source to become admitted. Since
`aefc7fa1` the gate also asks `policy_action.parse_action`, which still refuses.
Verified:

```
policy_action.parse_action(None) -> ActionRefused: action must be an object
```

The test's premise ("ask the contract to accept None and the source is
admitted") no longer holds when there are two contracts and it patches one. Also
stale.

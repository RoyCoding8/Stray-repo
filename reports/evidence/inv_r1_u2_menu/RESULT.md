# M3 cannot be made informative from the current source, and the reason is not the model

`inv_r1_u2_menu`, lane U2, at `5f5ea22`. The generator is `make_result.py` in
this directory; `result.json` is its machine-readable output. Route
`openrouter/nvidia/nemotron-3-ultra-550b-a55b:free`, two disposable stores, no
operation against `ec02test_live`.

## The recorded gap is real, and it is not the gap the report names

`CONTROL.md` does exist and does move task utility from `not_comparable` to
`tie`. That correction is accepted. The gap is real underneath it. The control
is `reduce_software(..., method="ddmin")` and so was the acquired member, so
the tie is forced. The report's own words: "It is the authored baseline wearing
an acquired label."

`77feff2` answered that by removing the `ddmin` default from
`reducers.reduce_software` and `reduce_graph`, and by offering `ddmin_reduce`
and `greedy_reduce` to the constructor as separate callables. The contract now
says so in its own text: `method` is required and "there is no default".

## The fix changed the contract, not the thing the model runs

`method_exec.child_contract()` is what the constructor prompt is built from.
`method_exec._child_wrapper_source()` is spliced into the driver the child
process executes. The second is generated by one uniform template:

```python
"def %s(task, oracle, *, method=\"ddmin\", max_queries=16):\n"
"    return %s(task, oracle, method=method, max_queries=max_queries)"
```

for every callable with a binding, and the bound target is looked up by
`spec["binding"].split(".")[-1]`. Only `reduce_software` and `reduce_graph`
have that shape. The audit in `result.json` finds **13 problems across all six
entries**:

| callable | problems |
|---|---|
| `ddmin_reduce` | wrapper defaults `method` to `ddmin`; arity and names do not fit the binding |
| `greedy_reduce` | same two |
| `software_atoms` | same two |
| `graph_atoms` | same two |
| `reduce_software` | wrapper defaults `method` to `ddmin`; contract promises no default and the wrapper has one |
| `reduce_graph` | same two |
| `oracle.query` | declared in the contract, not wrapped |

## Two runtime probes confirm it is not a shape argument

Both ran through `method_exec.run_member_out_of_process`, the real child, the
real oracle socket and the real launcher, on `ad01-w2-within-sw-00`.

**A member written to the newly offered menu fails.**

```
TypeError: software_atoms() missing 1 required positional argument: 'oracle'
wall_ms: 42
```

`software_atoms(task)` is one positional argument. The wrapper passes two, plus
a `method` the function does not take. The two primitives the widening exists
to offer are unbuildable as the contract offers them.

**A member that trusts the contract's "there is no default" and omits `method`
succeeds, at 8 queries.** It cannot omit it, because the wrapper supplies
`ddmin`. The default the fix removed is still there, one layer out.

So the tie was not broken. Both members of the comparison still run
`ddmin_reduce` or `reduce_software` with `ddmin`, and a control is still
`seed-sw-ddmin`. The contrast is a tie by construction, exactly as recorded.

## The live route is up, free, and refused by a case comparison

The direct route diagnosis returns HTTP 200, `model` matching the frozen
`resolved_model` to the character, `tier` free, and `cost: 0`. The one field
that differs is `provider`, and it differs only in case:

| field | returned | frozen |
|---|---|---|
| `endpoint` | `http://127.0.0.1:4000/v1` | `http://localhost:4000/v1` |
| `model` | `nvidia/nemotron-3-ultra-550b-a55b:free` | identical |
| `provider` | `Nvidia` | `nvidia` |
| `tier` | `free` | `free` |

`gateway_http._response_meta` compares `route["provider"]` to
`expected.get("provider")` with `!=`, so a provider that spells its own name
with a capital letter is refused as a route mismatch, after the tokens are
already spent. `_returned_route` normalizes `provider` for presence but not for
case.

## Is the contrast informative this time

No, and not for the reason the gap document gives. The gap document says the
acquired member calls the control's own method. That is still true and it is
not the whole reason. The reason is that the menu change which was supposed to
make the choice measurable was never wired to the executable, so the model
never had a working alternative to choose. The gap document's own remedy,
"a menu whose default is not the answer", was implemented in the declaration
and not in the code the child runs.

This is a finding about the harness, and it is a complete result. It also means
M3 needs no dispatches to settle. The blocker is deterministic and offline, so
the 360-call cap sheet has nothing to spend on until the wrapper is generated
per-binding rather than from one template.

## What the tests missed, and why

`tests/test_inv_r1_method_menu.py` has four checks and all four pass. They read
`method_exec.child_contract()`, which is the declaration. Nothing asserts on
`_child_wrapper_source()`, which is what executes. `test_no_offered_reducer_defaults_to_one_strategy`
is written as `assert "method=" not in signature or "ddmin" not in signature`,
which for a signature with no `method=` is vacuously true, so it could not
have caught a default in the wrapper. A test that passes while the thing it
names is broken is the shape the project already records once.

## Not fixed here

Three defects, reported and not repaired, because repairing the wrapper or the
route comparison changes what every arm of every prior run means, and that is
a coordinator's call on a frozen campaign.

1. `method_exec._child_wrapper_source` generates one uniform signature for six
   heterogeneous bindings. Four cannot be called; two re-supply the `ddmin`
   default the contract denies.
2. `gateway_http._response_meta` compares `provider` case-sensitively, so a
   correct response from `Nvidia` is refused after the tokens are spent.
3. `reasoning_effort` is accepted by `broker._validate_model` for a chat-API
   route that rejects it, so an admitted operation can be refused for a
   parameter the validator declared legal.

Defect 2 alone blocks every live send on this route, which means the recorded
M3 result of "330 of 360 calls unspent" has a second cause beside the tie.

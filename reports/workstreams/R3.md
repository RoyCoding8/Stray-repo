# R3 — R01-007 evidence retraction + snapshot coherence

Branch: `codex/review01-r01-evidence`, worktree `/home/ubuntu/AI/Agent-Society-v2-r01-evidence`.
Finding: `reviews/REVIEW-01.md` R01-007 (P1). Requirements: TX-4, S2 gate, §15
stale-admissibility check. Spec: check expensive support outside the transition,
validate its evidence epoch at admission; no stale admissibility wins after the
retraction's admission order.

## Defects

1. `_supported` never checked whether its root claim was retracted, while
   `_live_premise` rejected the same claim as a premise (probe 4).
2. `current_support` traversed under READ COMMITTED, then read
   `evidence_epoch` afterwards: an invalidation landing in between produced
   stale-true support labeled with the new epoch.

## Fix (`src/settlement/evidence.py` only)

- One `_retracted(cur, ref)` predicate governs both paths: `_supported`
  returns `(False, [])` for a retracted root; `_live_premise` keeps its
  behavior through the same predicate.
- `current_support` brackets the traversal with two plain epoch reads and
  commits the cache only when they agree, retrying (up to 25 rounds) on
  mismatch. Every admissibility-affecting mutation commits its visibility
  change and its epoch bump atomically in one `store.transact` transaction,
  so equal brackets prove no invalidation landed mid-traversal: the
  `(support, epoch)` pair is one coherent snapshot. No locks are taken.

## Rejected approach (recorded so nobody retries it)

First attempt took `control ... FOR UPDATE` before traversing. It hung the
caller suites: `capabilities.scoped_release` calls `check_use` →
`current_support` on a new connection while its own `store.transact`
transaction holds the control lock — the inner read blocked on the outer
write in the same thread forever (observed via `pg_stat_activity`:
`transactionid` wait against an idle-in-transaction holder). Any locking
read is incompatible with in-transaction callers; revalidation keeps the
read lock-free.

## Tests (`tests/test_r01_evidence.py`, real PostgreSQL)

- Direct claim retraction kills root support; `check_use` raises after.
- Derivation-only retraction preserves alternate support, premise retraction
  of the survivor kills it.
- Retracted premise-claim kills dependent support and the claim itself
  (DB-level analogue of probe 4: root/premise consistent).
- Barrier-controlled invalidation between traversal and epoch read (hooked
  `_supported` + `pg_locks` waiter detection): snapshot never reports stale
  true with the newer epoch; true implies the pre-invalidation epoch.

## Contract request (coordinator; needs a db.py/isolation owner)

No `db.py` edit was needed. Residual dependency is conventional, not
enforced: coherence holds only while every admissibility-affecting mutation
commits its visibility change and its `evidence_epoch` bump atomically in
one `store.transact` transaction. Requested: document that invariant where
the mutations live (or in `db.py` as the evidence-write contract) so a
future path that mutates admissibility without an atomic epoch bump cannot
silently reopen the stale-label race. No code change is proposed beyond the
comment/contract; everything enforceable was implemented in `evidence.py`.

## Residual risks

- Under a sustained invalidation storm (25 consecutive mid-read commits)
  `current_support` raises `SettlementError` instead of returning a possibly
  incoherent snapshot. Ordinary contention agrees on round one; the bound
  only trips under adversarial churn.
- `check_use`'s pre-check (`get_control` then `current_support`) is still
  two steps, but it re-evaluates fresh and admission-time epoch validation
  stays the caller's TX-4 duty — outside this finding's scope.
- Claim retraction kills admissibility computationally; `derivations.status`
  rows stay `'valid'`. Consumers reading `status` directly as "admissible"
  would miss claim-level retraction; checked 2026-09-09, the only
  non-display consumer (`artifacts._sole_active_evidence`) defers to
  `current_support`.

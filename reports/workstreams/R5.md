# Workstream R5: REVIEW-01 deadline + UI findings (R01-014 gateway, R01-015, R01-S01)

Branch: `codex/review01-r01-deadline-ui`, base `381346a`.
Scope: gateway-side deadline enforcement, operator-view route retention and
scoped projections, bounded overview projection. The R01-014 store-side lock
bound belongs to another owner and is untouched here.

## R01-014 — elapsed deadline enforced at the gateway execution boundary

`src/settlement/gateway_http.py`: `infer` now reads the response through
`client.stream` with the computed timeout passed per request, so injected
clients receive the override instead of keeping their own timeout. The body
is consumed via `iter_raw` with an elapsed-deadline and cancellation check
per chunk: a server that keeps delivering bytes trips the total attempt
deadline promptly instead of producing a late `TIMEOUT` label. All cancel
paths return `CANCELLED`/`retryable=False` with an unknown-outcome note, so
callers must retain uncertain exposure and reconcile rather than resend.
Discovery/auth probes pass the same per-request override.

Subtlety found by probe: `Response.iter_bytes(chunk_size=65536)` buffers
through `ByteChunker` and yields only at 64 KB, which defeats per-chunk
deadline checks on small trickle bodies; `iter_raw` yields per arrival.

## R01-015 — detail views keep their route; scoped evidence; stored comparisons

`templates/base.html`: the polling div uses `{{ poll_url }}`; every route in
`src/settlement/api.py` passes its own path, so polling re-renders the
current view instead of replacing it with the overview.
`investigation_data`: attempt-scoped rows carry `LIMIT`s; T4 observations are
filtered to the investigation's attempts; derivations join through
`derivation_premises` to those observations; `evidence_relations` match only
refs of this investigation (attempts, operations, observation receipts,
scoped claim ids). `learning_data` builds `comparisons` from stored
`trial_protocols` plus per-arm outcome aggregates and `expenditure_ledger`
sums; `learning.html` renders them, `investigation.html` renders the scoped
observations/derivations/relations.

## R01-S01 — one bounded overview projection with shared derivation

`src/settlement/agenda.py`: `agenda_snapshot` takes `attempt_limit`
(default 50), returns `attempt_total`, orders active attempts first, and
bounds unresolved operations (200). `derive_next_decision` is a pure
function over `(lifecycle, ops)`; `next_decisions_for` resolves any id list
with one connection and one `LEFT JOIN` query; `next_decision_for` is a
wrapper over it. `overview_data` and `investigation_data` use the batch
path. Overview renders "showing N of M".

## Open risks

- Gateway wall-clock bounds cover connect/write/read/total waits; a
  hung TLS handshake inside the pool or proxy layer is bounded only by the
  connect timeout, and PostgreSQL lock/statement bounds remain with the
  store-side owner.
- Exposure retention after cancellation is the gateway's contract signal
  (`CANCELLED`, non-retryable, unknown outcome); durable uncertainty
  accounting lives in broker/store paths outside this slice.
- Overview page is first-50 by active-first ordering; older history is
  counted but not listed (no cursor paging yet).
- Investigation derivation scoping follows observation premises; derivations
  linked only to claims without observation premises are out of scope for
  that view by design.

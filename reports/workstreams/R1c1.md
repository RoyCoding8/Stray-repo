# R1c Part 1 — R01-003/004 contract fallout healing

Branch: `codex/review01-r01-admit` (on `1369711`, R1a/R1b intact).
Scope: R1c Part 1 only. No checkpoint/restore, wf continuation, or DB deadlines.

Owned paths touched: the six tests encoding pre-R01-003/004 contracts,
`scripts/scheduler.py` (explicit re-dispatch only),
`src/settlement/launcher_local.py` (generation-aware claim only),
`src/settlement/broker.py` (`redispatch_after_reset` helper only),
new `tests/test_r01c_redispatch.py`, this report. Nothing else.

## Source changes

`launcher_local.py`: `dispatch` records the admitted
`BrokerOp.dispatch_generation` in a `.gen` sidecar at claim time and fences
on it. A claimant that loses the atomic pid claim but sees a different
recorded generation refuses with `superseded-claim`, overwriting the record
only when its own generation is newer (max-wins, so a stale claimant can
never clobber a newer record). A claimant that wins the pid claim yet sees a
newer recorded generation refuses with `superseded-generation` before
spawning. `prove_never_sent(operation_id, dispatch_generation=None)` now also
voids on `.gen` records; the optional generation binds the proof to the
admission being reset (consumed by the scheduler path).

`broker.py`: added `redispatch_after_reset` — explicit operator path that
calls `store.reset_dispatch` with `expected_generation` (refusal returns a
`reset-refused-<code>` status, no send) and otherwise delegates to
`dispatch_operation`. `reconcile` is untouched and stays non-sendable.

`scheduler.py`: added `redispatch_reset`, which couples a never-sent proof
(`refused-prior-claim`, no DB mutation) to the generation-fenced broker
helper. Docstring updated: reconcile never returns advanced-unsent ops to
prepared. `agenda.repair_scan` needed no change: after an explicit reset the
op is prepared and the normal scheduler loop converges it.

## Per-test migration justification

- `test_state_investigations.py` (2 fulfill tests): bare payloads the new
  contract refuses now send the full pins (`attempt_id`,
  `ownership_generation`, `revision`, `authority_version`, `evidence_epoch`,
  `obligations`) via a local `_fulfill` helper, with `expected_revision` set.
  The amend test acquires/completes a second attempt at revision 2, since an
  attempt is pinned to its revision. Early-fulfill (`INVALID_INPUT`) and
  stale-revision (`STALE_REVISION`) assertions are unchanged.
- `test_adv_budget.py::test_fulfill_once_per_revision`: same full-payload
  migration; the duplicate keeps asserting non-`APPLIED` plus
  "already fulfilled".
- `test_s2_evidence.py::test_stale_admissibility...`: stale case pins all
  fields except a pre-retraction `evidence_epoch` (still `MISSING_EVIDENCE`,
  since retract bumps the epoch); fresh case carries the current epoch
  (still `APPLIED`). The test intent — stale admissibility loses — is
  preserved instead of collapsing into a missing-field refusal.
- `test_r01_authority.py::test_r01_001_replayed_advance...`: admit +
  revalidate now issue 3 `_advance` calls for 2 racers, so the mock answers
  `APPLIED` once and `ALREADY_APPLIED` thereafter; assertions keep the
  one-send intent (exactly one `applied`, one gateway call, `[False, True]`
  statuses). The `_finish_send` mock takes the new fourth
  (`generation`) argument.
- `test_reconcile_reset.py::test_advanced_but_unsent...`: reconcile no longer
  yields `needs-prepare`. The test now drives the explicit helper: wrong
  `expected_generation` refuses with `reset-refused-stale_revision` and sends
  nothing; the live generation resets and redispatches exactly once (one
  `.spawns`). Reconcile-parks coverage stays with the sibling tests
  (`post_claim_crash`, `wiped_run_state`, `cancel_requested`,
  `recorded_receipt`), unchanged.
- `test_agenda_repair.py::test_repair_scan...`: `run_once` no longer
  converges advanced-unsent ops. `op1` goes through the explicit scheduler
  path (`redispatch_reset` → `observed`, one send); `op2` proves the repair
  scan parks (`unresolved`, listed in `repaired`, never sent). Wakeups still
  asserted.
- New `tests/test_r01c_redispatch.py`: `.gen` record + proof semantics;
  dispatcher paused before the launcher claim fenced by an interleaving
  reset (one spawn, stale dispatcher sends nothing); dispatcher paused after
  the claim never spawns once a newer generation records (no `.spawns`, no
  result). This closes the R1b open risk "paused inside `LocalLauncher`
  .dispatch"; the residual fully-concurrent race still lands in the broker
  post-send fence (`unknown` receipt, exposure retained).

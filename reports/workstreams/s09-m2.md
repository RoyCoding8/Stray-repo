## What was built

Versioned `STEP(view,state)` artifacts execute exclusively in the
bounded local-process child reusing the ENTRY runner machinery:
`verify_step_source` (exact `STEP(view,state)` arity, no imports,
dunder, IO or reflection), `_STEP_DRIVER` (no oracle socket, no host
bindings; least privilege), `run_step_out_of_process` with CPU, wall,
output and state caps through broker `sandbox-exec` with durable
receipt reuse by operation id. `policy_step.py` owns view
materialization, artifact make/verify with source-digest check,
step-result validation and single-row `s09_policy_state` persistence
(provenance `s09-m2`): full per-step view/result/transition lists plus
the terminal accepted investigation, written once before effects.
Intermediate crashes leave no half-row, so resume re-decides
idempotently through broker receipt reuse.

`StepPolicyConsumer` plugs into the public entry through the existing
`run_campaign(consumer=...)` seam with no driver edits. Generated
source never becomes a proposer callback (`_proposer` stays None);
every diagnose/construct/use action passes trusted
`admit_investigation` plus the downstream execution fence;
`request_model` becomes a broker `model-inference` op whose settled
text returns as the next STEP observation with digest; step and model
call budgets both bind the loop. `construct_policy` returns model
bytes with lineage, per-attempt response digests, gate plus child
dry-run validation and exactly one repair; double failure raises
honest `ConstructionFailed` with no authored fallback.

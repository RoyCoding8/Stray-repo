# Decisions

| ID | Requirement | Reason / evidence | Alternative selected | Consequence |
|---|---|---|---|---|
| D-001 | TECHNOLOGY-DECISIONS §2 (PostgreSQL 18) | Build host provides PostgreSQL 16.15; no PG18 available. Constraint logic uses standard SQL portable across both. | Develop and test against local PostgreSQL 16; declare PostgreSQL 18 as the deployment target and re-verify on first deployment. | S0 manifest records both; deployment gate stays open until tested on PG18. |
| D-002 | PRACTICAL-SPECIFICATION §6 (gVisor `runsc`) | No Docker/`runsc` on this host. Spec forbids silent unrestricted fallback. | Ship the `gvisor` execution profile probe-gated (reports explicit incompatible here); add an explicitly labeled `local-process` profile for bounded software-diagnosis work that never claims containment. | Isolation gate unverified on this host; reproducible setup deferred to a Linux/gVisor host. |
| D-003 | REVIEW-01 R01-001 (replay authority) | Only `APPLIED` authorizes a send; provider idempotency headers are not evidence and the local atomic claim does not cover the HTTP route. | Replay (`ALREADY_APPLIED`) returns existing state with zero sends; unique advance identity per attempt preserves legitimate post-reset redispatch. | `reviews/probes/historical_test_review_01.py` probe 2 asserts the old double-send; superseded by `tests/test_r01_authority.py`. |
| D-004 | REVIEW-01 R01-003 (fulfillment strictness) | Minimal fulfill payloads and unrelated-attempt fulfillment are review-mandated refusals; existing tests encoded the old contract. | Mandatory authority/identity/generation/revision/obligation validation in one transition; explicit `fulfill_investigation_override` (operator + reason, distinct event) is the only bypass. | Affected existing tests migrated to full payloads (`reports/workstreams/R1b.md`, `R1c1.md`). |
| D-005 | REVIEW-01 R01-004 (recovery semantics) | Auto-reset of unsent work to `prepared` plus resend lets a fenced sender transmit; an empty run directory proves nothing. | Reconcile stays non-sendable; explicit `store.reset_dispatch` with `expected_generation` plus explicit scheduler re-dispatch; dispatch-generation-aware launcher claim. | `test_reconcile_reset.py` / `test_agenda_repair.py` migrated; probe answer 2 superseded. |
| D-006 | REVIEW-01 R01-006 (restore fence) | A different database name does not fence a pre-restore dispatcher; generations must be replaced durably in the target. | `run_restore` applies `store.restore_fence` (new attempt generations, op dispatch-generation bumps) as one journaled `recovery.fenced` command in the target DB. | Restore target legitimately differs from the manifest by exactly that record (`tests/test_rec_restore.py` asserts it). |
| D-007 | REVIEW-01 R01-007 (snapshot coherence) | A locking read (`control FOR UPDATE`) deadlocks in-transaction callers (`scoped_release` → `check_use` on a new connection blocks on its own held lock, observed via `pg_stat_activity`). | Lock-free bracketed-epoch revalidation in `evidence.py`; atomic visibility-plus-epoch-bump invariant documented as the evidence-write contract. | Raises `SettlementError` instead of answering under sustained invalidation storms (>25 mid-read commits). |
| D-008 | REVIEW-01 R01-008 (grader isolation) | Candidate code sharing the grader process can forge success and reach hidden cases (reproduced). | Out-of-process candidate execution; evaluator parses one envelope line per case and owns the authenticated receipt; `_grade` success requires `passed == total == len(cases)`. | Partial-pass outcomes are now failures — consumers (R4b/R4c) adjusted. |
| D-009 | REVIEW-01 R01-011/012 (experiment honesty) | Discovery/auth probe plus printed suggestion is not an experiment; free-token doubles do not waive resource accounting. | CLI executes dev → freeze → matched A/B/C with broker-routed effects, receipt-reconciled costs, insufficient-grant refusal, exit 2 without live inputs; `simulated=True` evidence is non-releasable. | Live endpoint/key/funded grant still required for a real comparison. |
| D-010 | REVIEW-03 R03-001 (stale-sender fence) | A pre-check cannot fence a sender that prepares after the check; cross-database revocation is outside file-scope enforcement. | Single ownership check at the final pre-send boundary; a superseded sender unwinds its claim and is refused, letting the newer generation resume on retry; same-host concurrency keeps the docker `--name` collision as backstop. | Change during `run_gvisor` itself still relies on `--name`; cross-host fencing needs operator `stop()` plus restore fencing. |
| D-011 | REVIEW-03 R03-002 (fail-closed supervision) | Supervision cannot precede the container it supervises, so "establish first" means refusing to leave it running unsupervised. | Supervisor-start failure fences via `terminate_verified` and reports `supervision-unavailable`; timeout uses verified stop with tri-state tracking retained until termination is established. | `is_live` consults the runtime while tracking is retained; repair loop in `enforce_deadlines`. |
| D-012 | REVIEW-03 R03-002/010 (declared bounds) | Fixed 5 s allowance did not cover 15/30 s docker control ceilings; subsecond psycopg timeouts rounded to default. | `STOP_SETTLE_S` (80) derived from the actual ceilings feeds the sandbox hard-ceiling exposure; store re-arms statement timeouts per statement and bounds connection waits. | Reservations grew honestly; two fixtures migrated to fund the bound. |
| D-013 | REVIEW-03 R03-003 (contained staging) | Grading/method/capability paths passed host paths plus host interpreter with no staging. | One staging interface on the Launcher protocol (stage inputs, exec-visible dirs, python, output readback); runsc uses image-PATH `python3` by default with explicit `--runsc-python` override. | No real-container qualification on this host. |
| D-014 | REVIEW-03 R03-004 (evaluation binding) | Validators bound metadata but no executable/candidate/input digests; bare success certified outcomes. | Digests bound pre-launch, re-verified at launch and receipt admission; tallies required for digest-bound success. Legacy unpinned bindings keep prior semantics (documented boundary). | Direct API callers can still register digest-less evaluators. |
| D-015 | REVIEW-03 R03-005 (honest experiment) | C's executable result never reached the solver; synthesis was a fixed lookup. | Shared bounded tool envelope for all arms, real invocation results to C, exact lookup kept as labeled baseline, no-op ablation; inconclusive is valid, positive not required. | No empirical learning comparison (no live inference). |
| D-016 | REVIEW-03 R03-006/007/008/009 (recovery integrity) | Barrier watched ids not progress; pauses clobbered; no wakeup path; retries re-read one failure. | Quiesced barrier with step digests and pause ownership; idempotent repair-scan wakeup; fresh retry identities with terminal-failure decisions. | Live-DBOS backup interleaving still scripted, not executed. |
| D-017 | REVIEW-03 probe retirement | Two defect probes' doubles went stale against fixed call shapes. | Retired R03-011/R03-012 probes with named real-DB replacements in the probe header; all other probes migrated to fixed contracts in place. | Retirement log lives in the probe file header. |
| D-018 | DEV-01 entry/lifecycle integration | The entry labeled `run_abcs` internals with episode phase names, bypassing admission, count bounds and the selection gate. | Entry drives the durable lifecycle and injects the bound candidate via `synthesize` with `fixer_version` set to the bound version id; C invokes the exact bound bytes. | Multi-family episodes share one stem (seed is single-family). |
| D-019 | DEV-03 check semantics | Direct grading of candidate bytes can never pass procedure-shaped candidates (the specified final form). | `development.check` applies the intervention per development task (invoke, then grade repaired outputs); direct-grade path deleted, not kept as fallback. | D-EP tests migrated to task-shaped fixtures. |
| D-020 | DEV-12 repeatability | `run_abcs` re-proposed deterministic answer claims every run; second run on one DB crashed on `claims_pkey`. | `propose_hidden_answer` returns `ALREADY_APPLIED` on identical content, refuses divergent re-assertion; claim immutability untouched. | Bound episode ids refuse re-run on identity (correct). |
